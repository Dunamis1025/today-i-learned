# IPv6 Address Autoconfiguration (SLAAC, DHCPv6, EUI-64)

Study notes summarizing ICMPv6-based dynamic IPv6 addressing methods.

---

## 1. ICMPv6 RS and RA Messages

The foundation of dynamic IPv6 addressing is a two-message exchange using ICMPv6:

- **RS (Router Solicitation)** — Sent by a host to the *all-routers multicast address* when it needs addressing information. Essentially: "Is there a router here? I need network info."
- **RA (Router Advertisement)** — Sent by the router to the *all-nodes multicast address* in response (or periodically). Contains network prefix, prefix-length, and default gateway info, plus flags that tell the host *how* to get any additional information it needs.

**Solicitation** = a request/ask. Router Solicitation = "asking the router for information."

**Node** = any device connected to the network (host, server, router, printer, etc.) that participates using an IP address.

---

## 2. SLAAC (Stateless Address Autoconfiguration)

A host can build its own IPv6 Global Unicast Address (GUA) without any DHCP server, using two pieces:

| Part | Size | Source |
|---|---|---|
| **Prefix** | 64 bits | Provided by the router's RA message |
| **Interface ID** | 64 bits | Generated by the client device itself |

Example:
- Router advertises prefix: `2001:db8:acad:1::/64`
- Host generates Interface ID: `fc99:47ff:fe75:cee0`
- Final address: `2001:db8:acad:1:fc99:47ff:fe75:cee0/64`

The Interface ID can be created two ways:
1. **EUI-64 process** — derived from the device's MAC address
2. **Randomly generated 64-bit number** — used by default in most modern OSes for privacy

---

## 3. RA Message Flags: M and O

The RA message carries two flags that tell the host which addressing method to use:

| Flag | Full name | Meaning when set to 1 |
|---|---|---|
| **M** | Managed Address Configuration | "Get your IPv6 address from a DHCPv6 server" |
| **O** | Other Configuration | "Get extra info (like DNS) from a DHCPv6 server" |

If M = 1, the O flag becomes irrelevant — the DHCPv6 server provides everything anyway.

---

## 4. Three Methods of Dynamic IPv6 Addressing

### Method 1 — SLAAC Only (M=0, O=0)
- Router's RA provides: prefix, prefix-length, default gateway
- Host creates its own Interface ID (EUI-64 or random)
- No DHCPv6 server involved at all

### Method 2 — SLAAC + Stateless DHCPv6 (M=0, O=1)
1. Host sends RS: "I need addressing information."
2. Router sends RA: "Here's your prefix and default gateway. Get DNS info from a DHCPv6 server."
3. Host sends **DHCPv6 Solicit** to a **Stateless DHCPv6 Server**, which returns only extra info (DNS server address, domain name) — it does **not** allocate an address.

### Method 3 — Stateful DHCPv6 (M=1)
1. Host sends RS.
2. Router sends RA: "I am your default gateway, but get your IPv6 address and everything else from a stateful DHCPv6 server." (No prefix is given.)
3. Host sends **DHCPv6 Solicit** to a **Stateful DHCPv6 Server**, which allocates the full GUA, prefix length, and DNS info — and **tracks** which client has which address (like traditional IPv4 DHCP).

**Important rule:** Regardless of the method, the **default gateway address always comes from the router's RA message** — never from a DHCPv6 server (stateless or stateful).

### Comparison Table

| | Method 1 (SLAAC only) | Method 2 (SLAAC + Stateless DHCPv6) | Method 3 (Stateful DHCPv6) |
|---|---|---|---|
| IPv6 address | Host generates (SLAAC) | Host generates (SLAAC) | DHCPv6 server allocates |
| Default gateway | From RA | From RA | From RA |
| DNS / extra info | None | From Stateless DHCPv6 | From Stateful DHCPv6 |
| Server tracks clients? | No | No | Yes |
| M flag | 0 | 0 | 1 |
| O flag | 0 | 1 | — |

---

## 5. Stateless vs. Stateful (Concept)

- **Stateful** — The server records and manages *who has which address* (like a hotel front desk keeping a guest log). This is how traditional IPv4 DHCP works.
- **Stateless** — The server answers requests for information but keeps no record of who asked (like a tourist info booth). It never allocates addresses.

---

## 6. EUI-64 Process

**EUI-64** = Extended Unique Identifier – 64-bit. An IEEE-defined method for turning a 48-bit MAC address into a 64-bit Interface ID.

### Steps (Example MAC: `fc99:4775:cee0`)

1. **Split the MAC address** into two 24-bit halves:
   - OUI (vendor code): `fc:99:47`
   - Device Identifier: `75:ce:e0`
2. **Insert `fffe`** (16 bits) in the middle:
   - `fc:99:47 | ff:fe | 75:ce:e0`
3. **Flip the 7th bit (U/L bit)** of the first byte of the OUI:
   - `fc` (`1111 1100`) → `fe` (`1111 1110`)

**Result:** `fe99:47ff:fe75:cee0`

### Key Points
- **U/L bit** = Universal/Local bit, indicates globally-unique management; flipped per IEEE convention (RFC 5342).
- If you see `fffe` in the middle of an IPv6 Interface ID, it was almost certainly generated via EUI-64.
- **Advantage:** Easy to trace an IPv6 address back to a specific device's MAC address (useful for network admins).
- **Disadvantage:** Same trait creates a **privacy risk** — the physical device can be tracked across networks. This is why most modern operating systems now default to a **randomly generated Interface ID** instead of EUI-64.

---

## Quick Recap

- **RS/RA** = how a host discovers a router and gets basic network info via ICMPv6.
- **SLAAC** = host builds its own full IPv6 address (prefix from router + self-made Interface ID).
- **Method 1/2/3** = three ways to combine SLAAC and DHCPv6, controlled by the M and O flags in the RA message.
- **Stateful vs Stateless** = whether the DHCPv6 server tracks address assignments (stateful) or just answers info requests (stateless).
- **EUI-64** = one way to build the Interface ID from a MAC address (vs. the random alternative), with a trade-off between traceability and privacy.
