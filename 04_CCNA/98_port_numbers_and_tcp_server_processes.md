# Port Numbers and TCP Server Processes

Study notes from CCNA Module 14: Transport Layer — Section 14.4 (Port Numbers) and 14.5.1 (TCP Server Processes).

## 14.4.1 Multiple Separate Communications

- TCP and UDP transport layer protocols use source and destination port numbers to keep track of multiple, simultaneous communications.
- The header of each segment/datagram contains a **source port** and a **destination port**.
- The **destination port number** is associated with the destination application on the remote host.
- The **source port number** is randomly generated by the sending device and is used to track and differentiate a specific conversation, and to track multiple conversations between devices.
- This allows multiple applications on the same host to communicate simultaneously without their data being confused with one another.

## 14.4.2 Socket Pairs

- The source and destination ports are placed within the segment. The segments are then encapsulated within an IP packet.
- The IP packet contains the IP address of the source and destination, and the destination and source ports are contained in the TCP or UDP segment header.
- The combination of the transport layer port number and the network layer IP address identifies a **socket**:

  `socket = IP address : port number`

- A pair of sockets (source socket and destination socket) uniquely identifies a specific conversation between two devices — this is called a **socket pair**.

**Example (from the module diagrams):**

| Connection | Source Socket | Destination Socket |
|---|---|---|
| FTP connection | 192.168.1.5:1305 | 192.168.1.7:21 |
| Web connection | 192.168.1.5:1099 | 192.168.1.7:80 |

- Even though both connections share the same source and destination IP addresses, the differing port numbers keep the two sessions completely distinct.
- The socket is used to identify the server and service being requested by the client. The client socket port number is used to track and differentiate multiple conversations between hosts.

## 14.4.3 Port Number Groups

The Internet Assigned Numbers Authority (IANA) is the standards body responsible for assigning various addressing standards, including port numbers. IANA divides ports into three groups:

| Port Group | Number Range | Description |
|---|---|---|
| **Well Known Ports** | 0 – 1023 | Reserved for common/standard services and applications (e.g., web browsers, email clients). Defined for both client and server processes. |
| **Registered Ports** | 1024 – 49151 | Assigned to user processes or applications. Processes are primarily individual applications a user chooses to install rather than common applications that would receive a well-known port. |
| **Private/Dynamic Ports** | 49152 – 65535 | Also known as ephemeral ports. Usually dynamically assigned to client applications when initiating a connection. Rarely used to identify a service. |

**Note:** Some server processes are given port numbers within the registered port range instead of well-known port numbers. The IANA website is used to view the full list of port numbers and associated applications.

## 14.4.4 The netstat Command

- Unexplained TCP connections could pose a security threat, since they may indicate that something or someone is connected to the local host.
- `netstat` is used to identify active TCP connections on a Windows host. It lists the protocol in use, the local address and port number, the foreign (remote) address and port number, and the connection state.

**Example output:**

```
C:\> netstat
Active Connections

  Proto  Local Address          Foreign Address        State
  TCP    192.168.1.124:3126     192.168.0.2:netbios-ssn ESTABLISHED
  TCP    192.168.1.124:3158     207.138.126.152:http   ESTABLISHED
  TCP    192.168.1.124:3159     207.138.126.169:http   ESTABLISHED
  TCP    192.168.1.124:3160     207.138.126.169:http   ESTABLISHED
  TCP    192.168.1.124:3161     sc.msn.com:http         ESTABLISHED
  TCP    192.168.1.124:3166     www.cisco.com:http      ESTABLISHED
  (output omitted)
C:\>
```

- Well-known destination ports (e.g., 80, 21) are often displayed by their service name (`http`, `netbios-ssn`) instead of the raw port number.
- A connection state of `ESTABLISHED` means the session has been successfully set up and is currently active.

## 14.5.1 TCP Server Processes

- Each application process running on a server is configured to use a port number, either automatically assigned or manually configured by an administrator.
- **An individual server cannot have two services assigned to the same port number within the same transport layer service.** (e.g., a web server and a file transfer application cannot both use TCP port 80 on the same host.)
- An active server application assigned to a specific port is considered **open** — the transport layer accepts and processes segments addressed to that port. A server can have many ports open simultaneously, one for each active application.

### Scenario

- **Client 1** requests web services (HTTP) from a server.
- **Client 2** requests email services (SMTP) from the same server.

### Request Destination Ports

- Clients use the **well-known port number** as the destination port to specify exactly which service they want.
- Client 1 (HTTP request) → destination port **80**
- Client 2 (SMTP request) → destination port **25**

### Request Source Ports

- Clients dynamically generate a **source port number** for each request (from the dynamic/private port range).
- Client 1 → source port **49152**
- Client 2 → source port **51152**

### Response Destination Ports

- When the server responds, it **reverses** the source and destination ports of the initial request.
- The server uses the client's original **source port** as the **destination port** of the response.
- HTTP response → destination port **49152** (Client 1's original source port)
- SMTP response → destination port **51152** (Client 2's original source port)
- This ensures the response is delivered back to the exact client/application session that made the request.

### Response Source Ports

- The server uses the client's original **destination port** as the **source port** of the response.
- HTTP response → source port **80**
- SMTP response → source port **25**

### Summary Table

| | Request (Client → Server) | Response (Server → Client) |
|---|---|---|
| **Source Port** | Client's dynamic port (e.g., 49152) | Server's well-known port (e.g., 80) |
| **Destination Port** | Server's well-known port (e.g., 80) | Client's dynamic port (e.g., 49152) |

**Key takeaway:** The source and destination ports used in a request are completely swapped in the corresponding response. This swap is what allows the client to correctly match an incoming response to the request it originally sent, and allows the server to keep multiple client sessions distinct — even when multiple clients request different services (or the same service) at the same time.

## Related Concept Clarifications

- **Physical port vs. logical port:** A physical port (e.g., the Ethernet jack on a router) is a hardware interface for plugging in a cable (OSI Layer 1). A logical port (e.g., TCP/UDP port 80) is a software concept used to identify which application on a device should receive incoming data (OSI Layer 4). They share a name but are unrelated concepts.
- **VLAN vs. port number:** A VLAN (Virtual LAN) logically groups a switch's *physical* ports into separate broadcast domains by department/purpose (OSI Layer 2). A TCP/UDP port number identifies an application/session on a single host (OSI Layer 4). They operate at different layers and serve entirely different purposes.
- **TCP/IP stack:** Refers to the layered set of networking software built into an operating system (Application, Transport, Internet, Network Access layers) that processes data as it moves up or down through the layers — not to be confused with the "stack" data structure (LIFO) in computer science.
