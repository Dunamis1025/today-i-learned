# Secure Network Devices — Configuration & Verification (Packet Tracer)

## Overview

Hands-on lab securing a small topology (R1 router — S1 switch — PC-A) using Cisco IOS best-practice security commands. Covers basic device setup, password hardening, SSH-only remote access, login attack mitigation, unused port lockdown, and full verification testing.

**Topology**
```
PC-A (192.168.1.3/24) — S1 (VLAN1: 192.168.1.11/24) — R1 (G0/0/1: 192.168.1.1/24)
```

---

## Part 1: Basic Device Configuration

### Router (R1)
```
enable
configure terminal
hostname R1
no ip domain-lookup
enable secret class
line console 0
 password cisco
 login
line vty 0 15
 password cisco
 login
banner motd #Unauthorized access is strictly prohibited#
interface gigabitEthernet 0/0/1
 ip address 192.168.1.1 255.255.255.0
 no shutdown
copy running-config startup-config
```

### Switch (S1)
Same pattern, but IP goes on the **SVI (Switched Virtual Interface)**, not a physical port:
```
interface vlan 1
 ip address 192.168.1.11 255.255.255.0
 no shutdown
```

### PC-A
Static IP: `192.168.1.3 / 255.255.255.0`, gateway `192.168.1.1`. Verified connectivity to both R1 and S1 with `ping`.

## Part 2: Security Hardening

### Password Encryption & Policy
```
service password-encryption          ! encrypts all clear-text passwords in config
security passwords min-length 12     ! new passwords must be 12+ characters
                                      ! (does NOT retroactively affect passwords already set)
```

### Strong Passwords (applied to both R1 and S1)
| Purpose | Password |
|---|---|
| Privileged EXEC (`enable secret`) | `$cisco!PRIV*` |
| Console | `$cisco!!CON*` |
| VTY | `$cisco!!VTY*` |
| SSH admin account (`username SSHadmin secret`) | `55HAdm!n2020` |

> **Key insight (Reflection Q1):** Once console/VTY passwords are overwritten with the stronger versions, the original `password cisco` is never used again — it's fully replaced. Also, once `login local` is applied to VTY, line passwords stop mattering entirely for VTY — authentication uses the local username database instead.

### SSH Setup
```
ip domain-name ccna-lab.com
username SSHadmin secret 55HAdm!n2020
crypto key generate rsa      ! prompts for modulus size → 1024 bits
line vty 0 15
 transport input ssh         ! only SSH allowed in (Telnet blocked)
 login local                 ! authenticate against local username DB, not line password
```

### Session & Login-Attack Protections
```
line console 0
 exec-timeout 5 0            ! disconnect after 5 min idle
line vty 0 15
 exec-timeout 5 0
login block-for 120 attempts 3 within 60
   ! if 3 login failures occur within 60 seconds,
   ! block ALL logins (even valid ones) for 120 seconds ("Quiet-Mode")
```
> **Note:** `login block-for` worked on the router (4221) but returned `% Invalid input` on the switch (2960) — this command is not supported on that switch/IOS image in Packet Tracer. Confirms that security feature support varies by platform.

### Disabling Unused Ports
```
show ip interface brief                    ! identify unused interfaces
interface range fastEthernet 0/3 - 24
 shutdown
interface range gigabitEthernet 0/1 - 2
 shutdown
```
Only Fa0/1 (→R1) and Fa0/2 (→PC-A) left active; all others explicitly `administratively down`.

## Part 3: Verification Testing

| Test | Result |
|---|---|
| Telnet to R1 / S1 | Connection opened then immediately closed — blocked by `transport input ssh` |
| SSH to R1 / S1 as `SSHadmin` | Success; banner (`Unauthorized access is strictly prohibited`) displayed |
| 3x failed SSH logins within 60s | Triggered Quiet-Mode; `show login` confirmed `Router presently in Quiet-Mode`, all logins denied for the remaining block period |
| After 120s block period | `%SEC_LOGIN-5-QUIET_MODE_OFF` logged automatically; login access restored |
| 3x wrong `enable` password (after already logged in via SSH) | Session was **not** disconnected — `login block-for` only protects the login/authentication stage, not the `enable` privilege escalation stage. Just returns `% Bad secrets` and lets you retry. |
| `show running-config` | Confirmed encrypted passwords, `sl_def_acl`, VTY/console settings, banner, interface states |

## Key Concepts Learned

**Protocol** — an agreed-upon set of rules computers follow to communicate (e.g., SSH, Telnet, HTTP, TCP, IP).

**RFC (Request For Comments)** — the official internet standards documents that define how protocols must behave, agreed on globally so different vendors' equipment can interoperate.

**ACL (Access Control List)** — an ordered list of `permit`/`deny` rules (like a building's visitor list) used to filter traffic by IP, port, or protocol.

**`sl_def_acl`** — "Secure Login Default ACL." Auto-generated by IOS the moment `login block-for` is configured; used internally to define which traffic (Telnet/HTTP/SSH) counts toward the login-attack watch, not something to be hand-edited.

**IOS Syslog Message Format** — `%FACILITY-SEVERITY-MNEMONIC: message`
- Severity ranges 0 (Emergency, most critical) → 7 (Debugging, least critical)
- `%LINK-5-CHANGED` / `%SSH-5-ENABLED` → severity 5 (Notification) — normal state changes
- `%SEC_LOGIN-1-QUIET_MODE_ON` → severity 1 (Alert) — a potential security event needing attention

**`transport input ssh`** — restricts which protocols may be used to remotely connect *into* a line; setting it to `ssh` disables Telnet on that line.

**`login local`** — authenticate using the router/switch's own locally stored username database (`username ... secret ...`) instead of just a shared line password. Opposite approach: external AAA servers (RADIUS/TACACS+).

**SSH version "1.99"** — IOS compatibility notation (per RFC) meaning the device primarily runs SSH v2 while still accepting v1 clients for backward compatibility.

**Device model numbering (e.g., ISR 4321, Catalyst 2960-24TT)** — not a strict formula, but generally: leading digit = generation/performance tier, following digits = model/line within that generation, and suffixes describe physical specs (e.g., `-24TT` = 24 ports, copper Ethernet uplinks).

## Reflection Questions

**Q1: When is the original `password cisco` (set in Part 1) still used after hardening?**
A: Never — it's fully overwritten by the new console/VTY passwords, and VTY authentication switches to `login local` (username-based) entirely.

**Q2: Does `security passwords min-length 12` affect passwords shorter than 10 characters that were already configured?**
A: No — the policy only applies going forward to newly-set passwords; it does not retroactively invalidate or remove existing shorter passwords.
